Two ways in

Stay in Claude Code, or let it run on its own.

The Stop hook

handoff init adds a Claude Code Stop hook. Claude can't call it done until Kane agrees. A failure becomes its next instruction.

❯ Add a FAQ question "Is there a student discount?"
● Update(public/index.html) · Added 1 line
✻ Handoff: verifying the spec in a real browser…
Stop says: Handoff ✔ 6/6 checks verified by Kane CLI

The headless loop

handoff loop runs on its own: verify, brief Claude Code, re-check, sweep. Locally or in CI.

── Round 1 · Kane CLI verifies the build
✖ FAIL The Grow plan shows $60 per year, not $48.
◆ edit public/app.js

Use it on your project

Write what "done" means once. Kane checks it every time.

Think of it as a QA teammate for your coding agent. You stop being the one who clicks through and catches its mistakes.

01 · Once per computer

Install the tools

Node 18+, Google Chrome and Claude Code, plus Kane CLI with a free TestMu AI account. Then Handoff itself.

npm i -g @testmuai/kane-cli
kane-cli login
npm i -g github:esteexbt/handoff
02 · Once per project

Set it up in your app

Run this in your project folder. It creates handoff.md and connects Handoff to Claude Code.

cd my-app
handoff init --url http://localhost:3000
03 · Write what "done" means

Plain English, one line per check

How to start the site, then what someone should see when they use it. The way you'd brief a developer.

## Checks
- signup: Submit the form with "ada@example",
  verify it shows "Enter a valid email"
04 · Then just build

Claude can't say done until Kane agrees

Work with Claude Code as usual. Each time it finishes, Kane tests your checks in Chrome. Anything broken goes straight back to Claude to fix.

✻ Handoff: verifying in a real browser…
Stop says: Handoff ✔ 6/6 checks verified
